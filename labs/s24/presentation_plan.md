# 최종 발표 진행표 (팀당 10분 + 질의 5분)

| 시간 | 내용 | 발표자 | 준비물 |
|---|---|---|---|
| 0:00–2:00 | 문제: 현행 업무와 실측 시간 | 현업 담당 | 업무 단계표 |
| 2:00–5:00 | 데모: 실제 문서로 시연 | 개발 담당 | 녹화본(백업) |
| 5:00–7:00 | 숫자: ROI·회수 기간·민감도 | PM | roi.py 결과표 |
| 7:00–9:00 | 위험·통제와 실행 계획 | PM | 심의 자료 요약 |
| 9:00–10:00 | 요청 사항 한 장 | 팀장 | 결정 필요 일자 |

## 평가 기준 (청중 채점, 각 1~5점)
- 문제가 실측 숫자로 제시됐는가
- 데모가 실제 업무 데이터 형태로 동작했는가 (민감정보 제외)
- ROI 가정이 명시되고 보수적으로 잡혔는가
- 규제·보안 통제가 구체적인가 (담당자·주기)
- 다음 단계와 요청 사항이 분명한가

## 예상 질문 대비
- "절감 시간은 어떻게 쟀나?" → 인터뷰 + 최근 3개월 보고서 건수, 파일럿에서 실측 예정
- "틀린 답을 내면?" → 사람 검토 필수, 원문 병기, 오류 신고 버튼과 주간 점검
- "외부로 데이터가 나가나?" → 사내 승인 모델, 외부 전송 없음, 마스킹 로그만 보존
